# 桌面端待办任务管理工具 · 需求文档

> 文档状态：需求已确认（2026-11-23）
> 创建日期：2026-11-23

## 1. 背景与目标

本项目是一款桌面端待办任务管理工具，定位为轻量、低资源占用的个人任务管理应用：用户可在桌面端快速记录、查看、编辑并完成待办事项。项目有两条硬性诉求：①低内存占用——应用需作为常驻程序长期运行，内存占用必须尽可能低，不能成为日常使用的负担；②对外提供 MCP（Model Context Protocol）服务——应用需对外暴露标准 MCP 接口，使 AI agent（如 Claude Desktop、Claude Code 等）能够调用本工具对待办事项进行增、删、查、改操作，实现"用 AI 管理待办"的能力。

## 2. 已确认需求

以下条目为当前已明确确认的需求（含 2026-11-23 已决策事项，详见第 5 节决策记录）：

| # | 需求项 | 说明 |
|---|--------|------|
| 1 | 桌面端工具 | 应用形态为桌面端应用（非 Web 端、非移动端） |
| 2 | 待办任务管理 | 核心功能为待办任务的记录与管理 |
| 3 | 低内存占用优先 | 低内存占用为硬性诉求，是技术方案选型的首要约束 |
| 4 | 对外提供 MCP 接口 | "mcph"确认为 MCP（Model Context Protocol）笔误；应用对外提供 MCP 服务，供 AI agent 调用增删查改待办 |
| 5 | 目标平台 | Windows 优先，架构不锁死跨平台 |
| 6 | UI 形态 | 系统托盘常驻 + 主窗口结合（托盘满足常驻与快速访问，主窗口承载完整管理操作） |
| 7 | MVP 功能边界 | 任务增删改查 + 完成状态 + 优先级 + 到期时间；提醒通知、子任务、标签、循环任务列入二期 |
| 8 | 数据存储 | 本地 SQLite；多设备云同步列入二期 |
| 9 | MCP 传输方式 | stdio 起步（服务本机 agent），HTTP/SSE 按需后加 |
| 10 | 技术栈 | Tauri 2（Rust 后端 + 系统自带 WebView2），常驻内存约 30-60MB |

## 3. 候选技术方案对比

| 方案 | 常驻内存量级 | 平台支持 | MCP 集成难度 | UI 开发效率 | 结论 |
|------|------------|---------|-------------|-----------|------|
| Tauri 2 | 低（约 30-60MB，Rust 后端 + 系统自带 WebView2） | 跨平台（Windows / macOS / Linux） | 低（Rust 生态有 MCP SDK，可与后端同进程集成） | 中高（前端 Web 技术、生态成熟；跨 WebView 渲染一致性需注意） | **当前推荐** |
| Wails | 低（Go 后端 + 系统 WebView，与 Tauri 量级接近） | 跨平台（Windows / macOS / Linux） | 中（Go 生态有 MCP SDK，但较新、落地案例较少） | 中高（前端 Web 技术；组件生态小于 Tauri） | 备选 |
| WinUI 3 | 中（原生 XAML 框架，依赖 Win32/COM 运行时，量级居中） | 仅 Windows | 中（C# 有 MCP SDK，但与 UI 框架无耦合，需自行搭建服务层） | 低（XAML 学习曲线陡，第三方控件生态有限） | 不推荐（仅支持 Windows，UI 开发效率低） |
| Electron | 高（Chromium 进程常驻，常见 150MB 以上） | 跨平台 | 低（Node.js/TypeScript 生态 MCP SDK 最成熟） | 高（Web 技术，生态最成熟） | **排除**（内存占用过高，与低内存硬性诉求直接冲突） |

补充说明：Java/JVM 系方案（JavaFX / Swing）因 JVM 常驻内存通常达数百 MB，无法满足低内存目标，不推荐，故未列入上表。

## 6. 二期候选（明确不做进 MVP）

以下功能明确不纳入 MVP，作为二期候选：

1. **提醒通知** — 到期提醒与通知推送
2. **子任务** — 任务拆分与层级管理
3. **标签** — 任务分类与筛选
4. **循环任务** — 重复 / 周期性任务
5. **多设备云同步** — 跨设备数据同步
6. **HTTP/SSE 传输** — 面向局域网 / 远程 agent 的 MCP 传输方式
